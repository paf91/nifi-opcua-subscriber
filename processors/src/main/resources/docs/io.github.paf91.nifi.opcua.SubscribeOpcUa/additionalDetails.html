Bulk list

Paste one entry per line into Tags. Each entry may be a complete NodeId or an alias followed by a vertical bar and a NodeId.

Temperature | ns=2;s=Example.Tank.Temperature
Pressure | ns=2;s=Example.Pipe.Pressure
PumpRunning | ns=2;s=Example.Pump.Running

Use JSON when individual tags need different sampling intervals or monitored-item queue sizes:

[
  {"alias":"Temperature","nodeId":"ns=2;s=Example.Tank.Temperature","samplingIntervalMs":1000,"queueSize":100},
  {"alias":"PumpRunning","nodeId":"ns=2;s=Example.Pump.Running","samplingIntervalMs":250,"queueSize":200}
]

Individual properties

Alternatively, add a dynamic property named PumpRunning with value ns=2;s=Example.Pump.Running. Do not configure the same alias or NodeId twice across the bulk list and individual properties.

Namespace URIs and deadbands

Numeric addresses such as ns=2;s=Temperature keep using index 2. URI addresses such as nsu=urn:example:minute;s=Temperature resolve the server's NamespaceArray for each new session. Use the exact namespace for the intended data model; indexes do not define data frequency. URI subscriptions are recreated if a new session changes the namespace mapping. Missing URIs or duplicate resolved NodeIds fail the connection. Encode semicolons and percent signs in the URI as %3B and %25.

{"nodeId":"nsu=urn:example:minute;s=Temperature","deadbandType":"Absolute","deadbandValue":0.5}

Deadband types are None, Absolute and Percent. Absolute requires a finite nonnegative value; Percent requires 0–100 and the server's EURange property. Quality changes still produce notifications. A rejected filter fails the subscription; it is not silently removed.

Connection verification and monitoring

NiFi Verify opens a temporary session and subscription to check discovery, authentication/trust, namespace resolution and all configured monitored items. It closes them afterwards and emits no measurements. It may consume an additional server session. Results include endpoint choices, certificate expiry/fingerprints and revised settings.

Set Diagnostics Interval (seconds) above zero to emit JSON objects on the diagnostics relationship. The default is zero (disabled), and the relationship is automatically terminated unless routed. Reports include session activity, keep-alive and notification receipt times, negotiated settings, namespaces, buffer usage and cumulative drops. A quiet tag is not necessarily disconnected. Reports can be delayed by NiFi backpressure, and counters reset with the processor instance. Metadata details are capped; settingsMayBeStale indicates that a new session may have invalidated the initial namespace/negotiation snapshot.

Types and connection settings

Data types are read from the server; do not append Float, Double or Boolean to the NodeId. Obtain the endpoint URL and the server's security/authentication settings separately. Defaults remain Basic256Sha256, SignAndEncrypt and Username/Password. For secured channels, supply a client certificate/key; with Full or Certificate validation, also supply PKI Directory so client and server trust each other. Leave Application URI empty to derive it from the client certificate.

Server certificate validation

Server Certificate Validation defaults to Full: certificate trust, signatures, validity, usage, revocation, Application URI and endpoint hostname/IP are checked. Certificate skips only hostname/IP matching; approved server certificates or CAs must still be in PKI Directory, and the server's Application URI must still match its certificate URI SAN. For a literal IP endpoint, Full expects that IP in an IPAddress SAN. Fixing the server certificate or advertised endpoint is preferred.

None (insecure) bypasses the server certificate validator and ignores PKI Directory. It permits server impersonation, even if channel traffic is encrypted. It does not disable channel/session signatures, client certificate/key requirements, or server-side user authentication. Java can still reject a certificate whose critical key-usage extension forbids signing when verifying the server's session signature. These modes also apply when an unsecured channel uses encrypted username tokens. No mode automatically adds certificates to the trust list. A None/None channel with anonymous access or an unencrypted username token does not authenticate the server through a certificate, even with Full selected.

Stop, edit and restart to change the mode. Verify and diagnostics report the mode; successful verification with None does not prove server identity. Application URI always identifies this client; do not set it to the server's URI.

Endpoints without channel security

For username/password without a client certificate, set Security Policy to None, Security Mode to None, and Authentication to Username/Password. Supply credentials and Tags; leave the client certificate and key unset. If the server separately encrypts username tokens, Full and Certificate validation require a PKI Directory containing its trusted certificate. Otherwise, PKI is not needed and credentials are sent without encryption.

For anonymous access, select Anonymous and leave Username/Password unset. Anonymous on a secured channel still requires the client certificate/key and, with Full or Certificate validation, server trust. Without channel security, Application URI defaults to urn:nifi:opcua:subscriber. Endpoint selection never downgrades the requested settings.

Delivery limits

Notifications are buffered in memory. Stop/Start in the same JVM retains pending records; a JVM restart loses them. Buffers are local to each node. A full buffer drops new notifications. Defaults are 64 MiB of serialized buffered data, 1 MiB per record, and 4 MiB per success FlowFile. Count limits also apply. Maximum Record Bytes must fit the buffer and Maximum FlowFile Bytes minus two; batches account for brackets and commas. Oversized values are counted separately. These are serialized-data limits, not total JVM memory limits. Retained records use their original byte limits until drained. Primary-node failover can produce gaps or duplicates; the processor does not recover historical values.
