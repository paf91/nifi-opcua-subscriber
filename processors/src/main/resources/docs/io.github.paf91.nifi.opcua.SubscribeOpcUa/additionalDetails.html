Bulk list

Paste one entry per line into Tags. Each entry may be a complete NodeId or an alias followed by a vertical bar and a NodeId.

Temperature | ns=2;s=Example.Tank.Temperature
Pressure | ns=2;s=Example.Pipe.Pressure
PumpRunning | ns=2;s=Example.Pump.Running

Use JSON when individual tags need different sampling intervals or monitored-item queue sizes:

[
  {"alias":"Temperature","nodeId":"ns=2;s=Example.Tank.Temperature","samplingIntervalMs":1000,"queueSize":100},
  {"alias":"PumpRunning","nodeId":"ns=2;s=Example.Pump.Running","samplingIntervalMs":250,"queueSize":200}
]

Individual properties

Alternatively, add a dynamic property named PumpRunning with value ns=2;s=Example.Pump.Running. Do not configure the same alias or NodeId twice across the bulk list and individual properties.

Types and connection settings

Data types are read from the server; do not append Float, Double or Boolean to the NodeId. Obtain the endpoint URL and the server's security/authentication settings separately. Defaults remain Basic256Sha256, SignAndEncrypt and Username/Password. For secured channels, supply a client certificate/key and PKI Directory; client and server must trust each other. Leave Application URI empty to derive it from the client certificate.

Endpoints without channel security

For username/password without a client certificate, set Security Policy to None, Security Mode to None, and Authentication to Username/Password. Supply credentials and Tags; leave the client certificate and key unset. If the server separately encrypts username tokens, supply a PKI Directory containing its trusted certificate. Otherwise, PKI is not needed and credentials are sent without encryption.

For anonymous access, select Anonymous and leave Username/Password unset. Anonymous on a secured channel still requires the client certificate/key and server trust. Without channel security, Application URI defaults to urn:nifi:opcua:subscriber. Endpoint selection never downgrades the requested settings.

Included demo

The local demo exposes DemoSwitch | ns=2;s=Demo.Boolean. Its addresses are separate from the fictional examples above.

Delivery limits

Notifications are buffered in memory. Stop/Start in the same JVM retains pending records; a JVM restart loses them. Buffers are local to each node. A full buffer drops new notifications. Primary-node failover can produce gaps or duplicates; the processor does not recover historical values.
